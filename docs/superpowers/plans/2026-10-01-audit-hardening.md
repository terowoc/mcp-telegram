# Audit hardening after first deployment

User authorized the audit improvements after establishing the deployment pipeline. Continue inline under the same approved scope. The first deployment remains independently reviewable in PR1.

## Implementation sequence

1. **Session isolation:** derive lock/socket identity from the complete normalized absolute session path, not its directory. Resolve existing parent symlinks; Windows identity is case insensitive. Keep IPC endpoints short enough for Unix sockets. Add regression proving two session files in one directory acquire separate locks and cannot share endpoints. Capture cleanup paths when ownership is acquired, avoiding environment changes removing a different socket.
2. **Stable retries:** allocate Telegram deduplication randomIds before each retry closure for raw send requests (quoted/effect messages, dice/location/contact/venue, polls and stories). Regression injects a retryable failure after recording the request and asserts identical randomId across attempts. Preserve unrelated sends and do not send real Telegram messages in tests.
3. **Bounded IPC/executor:** incremental UTF-8 decoding, maximum frame size and queue length. Include a request deadline in IPC, reject expired queued requests before dispatch, and unify stdio/IPC tool execution. Keep the execution lock until an underlying timed-out operation settles or teardown confirms it stopped; never claim cancellation without evidence. Reject further dispatch while unhealthy and expose recovery status. Test late queue expiry without side effects, split Unicode, oversized frames and non-overlapping timed-out operations.
4. **Bounded reads/output:** reusable integer pagination limits in tool schemas, defaults and maximums for history/search/dialog/member reads; reject negative/fractional/excessive values before Telegram calls. Shared output budget in local/IPC/HTTP dispatch; preserve pagination hints. Add optional structured content where stable schemas can be expressed without changing existing textual content.
5. **Server policy:** configurable full/read/curated tool profiles enforced at the owner, not only discovery annotations. Optional canonical chat allowlist; deny unscoped/global operations that could leak chats when an allowlist is enabled, filter dialog enumeration, resolve aliases before comparing. Authentication/lifecycle tools retain explicit treatment. Tests use direct IPC to prove gateway bypass cannot evade policy.
6. **Workflow helpers:** read-only inbox aggregation with bounded pagination and a preparation tool that validates destination/content without sending; execution remains a distinct write tool. Add connection single-flight and a diagnostic `doctor` command with redacted status. Health/metrics expose operational counts without messages, tokens, API credentials or usernames.
7. **Maintenance:** update vulnerable transitive dependencies where compatible, synchronize dependency lockfiles, correct release automation for this fork without publishing upstream namespaces. Extract independently testable connection/media/executor/policy modules instead of a wholesale rewrite of the Telegram service. Document migration, profile usage, backups and rollback.
8. Verify meaningful regressions and existing suite, fresh branch review, integrate and deploy through the established Actions pipeline. Verify authorized Telegram status and persistence after the human QR step. Record remaining client-specific compatibility honestly.
